# ADR 001: Ταυτόχρονη χρήση Vaadin για το UI και REST endpoints για το OpenAPI
* **Ημερομηνία:** Νοέμβριος 2026

## 1.Το Πρόβλημα
Στο EscapeHub χρειαζόμαστε μια διαδραστική διαδικτυακή διεπαφή (UI) για τους παίκτες, την οποία η ομάδα επέλεξε να υλοποιήσει σε Java με το **Vaadin**. Ωστόσο, οι προδιαγραφές του μαθήματος απαιτούν επίσης την ύπαρξη και τεκμηρίωση ενός REST API μέσω **OpenAPI (Swagger)**. Το Vaadin επικοινωνεί εσωτερικά με τον server και δεν παράγει αυτόματα δημόσια REST endpoints για το OpenAPI.

## 2. Απόφαση
Αποφασίσαμε οτι:
1. Όλες οι οθόνες των παικτών υλοποιούνται με **Vaadin**.
2. Παράλληλα, δημιουργούμε επιλεγμένα **REST endpoints** (`@RestController`) για τις βασικές λειτουργίες που απαιτούν τεκμηρίωση OpenAPI.
3. Και το Vaadin και τα REST endpoints καλούν **ακριβώς τα ίδια Services**, όπου βρίσκεται όλη η επιχειρησιακή λογική δηλαδή οι κανόνες παιχνιδιού.

## 3. Συνέπειες (Θετικά & Αρνητικά)
* **Θετικά:** Καλύπτουμε 100% τις απαιτήσεις του μαθήματος Vaadin UI + OpenAPI, γράφουμε όλο τον κώδικα σε Java, και διατηρούμε τους κανόνες ασφαλείς σε ένα σημείο (Services) χωρίς διπλότυπο κώδικα.
* **Αρνητικά:** Χρειάζεται λίγος επιπλέον κώδικας για τη συγγραφή των REST controllers και προσοχή ώστε να μην μπει ποτέ λογική παιχνιδιού μέσα στις οθόνες ή στους controllers.
